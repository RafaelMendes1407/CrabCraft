# CrabCraft: features and status

For usage instructions, start with [your first project](docs/getting-started.md) or the
[main feature guide](docs/main-features.md). This inventory records implementation status,
verification evidence and remaining work; it is not a claim of parity with another IDE.

PR review (2026-11-13): Actions #175–#177 merged; the egui 0.37 migration
from #180 was completed with mouse-wheel events in the tests. Issue #181:
repository rustfmt uses width 160 and Max heuristics; this does not eliminate
the formatting debt is addressed by the later CI maintenance. Issue #173: the unified IDE proposal is documented in
`docs/architecture.md`, without implementing or promising a shared product/add-on.
The broad update #178 remains pending because of quick-xml compilation errors.
Source changes invalidate the previous static exception; it was not automatically renewed.

Security self-assessment infrastructure: dedicated workflow, local execution
through `scripts/security-audit.sh`, JSON/Markdown reports, per-crate SBOM,
`unsafe` inventory, Gitleaks and bounded fuzzing on scheduled/manual runs.
CI maintenance: repository-wide rustfmt and strict Clippy findings corrected;
the expired exact-source static baseline and downgrade logic are removed. Static
analysis now requires both commands to succeed. This changes no feature readiness
status and does not certify legal compliance or platform parity. Two exact historical
Gitleaks fingerprints from the formatting commit document the existing synthetic signature
fixture; its current value is now TEST-SIGNATURE to avoid repeated false positives.

Dependency audit (2026-11-12): `libsqlite3-sys` 0.39.1,
`pulldown-cmark` 0.13.6 and `rustix` 1.1.6 fix the RustSec advisories
identified in `short_audit.md`. CI checks advisories and licenses
with cargo-deny, vulnerabilities with cargo-audit, and generates a CycloneDX SBOM;
Dependabot tracks Cargo and GitHub Actions. `Session::clear` deletes a workspace's
session; `Settings::clear` deletes preferences and their backup. File indexing
remains in memory only and is discarded when the project closes.
Local file encryption, an audit trail and legal compliance
remain unverified and are not declared complete.

Inventory of what **RustRover 2026.2** offers, with each item's status in CrabCraft.
This is the project's tracking document: **update the status in the same commit that implements
the feature**.

Interface: the inherited NuGet manager and client were removed; settings have bounded
horizontal width, tool panels have margins, and edit/build/run/help menus,
a soft project halo and a transition at the tab drop destination were added. The test
`settings_keep_the_same_width_when_switching_pages` checks width across all categories
and height stability over 30 frames per category. Scrolling bounds both
dimensions to prevent the modal from continuously growing vertically.
Verified through UI tests and reviewed GPU captures; readiness statuses are unchanged.

DotCraft legacy cleanup: automatic Roslyn downloads from the NuGet feed and
netcoredbg downloads from Samsung releases, including fixed URLs, archives and progress
controls, were removed. Rust features continue to use their own adapters.
The C#/Razor parsers, their tree-sitter queries and the Visual Studio solution lexer
were also removed. Files in those languages now open as plain text;
syntax and editor benchmarks use generated Rust source.
The Roslyn LSP adapter was removed; shared LSP capabilities now live in
`rc-lsp/src/capabilities.rs`, used by rust-analyzer and configured web servers.
The netcoredbg DAP adapter and .NET debugging setup were removed; Rust sessions
continue with GDB/LLDB, including attach and remote debugging.
.NET project run configurations, builds and tests were
disconnected from the application; execution and testing use Cargo targets.
Workspace loading no longer detects Visual Studio solutions and projects, and
preferences no longer offer paths for .NET, Roslyn or netcoredbg.
The project explorer no longer reads .NET project XML or displays solutions and
MSBuild dependencies. The new-file menu offers only ordinary and Rust files.
The SDK, MSBuild, solution, project, run, .NET test and TRX modules were
removed from `rc-dotnet`, along with their fixtures. The crate retains its
name and only the types and process management used by Cargo and other Rust features.
Private Roslyn requests and the import-`using` action were removed from LSP.
File classifiers, test examples and translations no longer expose
the removed C#/.NET formats; protocol and Rust feature documentation URLs
remain where the product uses them.
`bin` and `obj` folders are visible again in the explorer and index; only
output and metadata folders relevant to Rust projects remain hidden.

Native main dropdown menu on the ☰ button, with 12 categories and submenus, shortcuts, all action-search
commands and tool access; the Project panel gained a searchable picker
for existing templates. Project identity uses a Gaussian blurred color in the top
bar, drawn in egui without new assets. While dragging, the editor displays a
gray overlay, docking map, filename and animated destination preview.
Evidence: edit/undo and file-creation tests in a Cargo project, GPU capture
`central_menus_and_docking_capture` and tab-movement regression. Local visual
references supplied by the user are not distributed with the application.

Settings › Tools: vertical form, with labels above fields and width
reserved for Browse; long text wraps and paths stay inside the field.
The page area uses an explicit vertical layout, respects the modal bounds and only shows
scrollbars when needed. Verified by `tools_settings_fields_fit_the_fixed_page_width`,
the category stability test and the `settings-tools-stacked.png` capture.

The template picker receives focus when opened, also filters searches with leading/trailing
spaces, allows choosing the first result with Enter and reports when there are no results.
The `template_picker_tests` tests cover immediate typing, Enter and searches without results.

Responsive settings: viewport-based width that stays stable across categories; compact
category selection in narrow windows and scrollable navigation when height is limited.
OK/Cancel remain accessible at logical sizes from 480×320 to 1280×800,
including 800×300. Browse in Tools is asynchronous and cancellable; the selection belongs
to the open draft and is discarded when it closes. Untrusted projects explain why
detection is disabled instead of showing an endless loading state. Tests:
`responsive_settings_tests`, `settings_browse`,
`untrusted_project_tool_settings_explain_why_detection_is_disabled`. The capture
`completed_interface_theme_and_size_capture` checks light/dark themes and compact windows
in a real Cargo project; images live in `target/snapshots/completed-*.png` (not distributed).

Menu availability: Run/Debug/Profile, Stop, debugger steps and configuration
editing respect selection, platform and session state. Unsupported actions
show their existing explanatory tooltips. The main dropdown, Tool Windows and Recent Projects
scroll within the stable viewport height without shrinking when the popup is repositioned.
Long project names are elided, with the full path on hover. Verified by the
four `ui::main_menu::tests` tests, including access to the last of 60 recent projects
and Help in a short window, plus command execution in the test Cargo project.

Tab docking completed for narrow cases: proportional guides without overlap,
with identical drawing and drop-target geometry; overlay and preview bounded to the group;
filename bounded to the window and drawn above the preview. Escape also cancels
dragging when received in the destination window. Verified by `docking_tests`, guide-based
docking, split/floating-window restoration and light/dark captures in Cargo projects.
