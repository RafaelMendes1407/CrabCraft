# Native Rust workspace in an already-running container

Open **Remote Rust workspace**, select **Use an already-running Docker container**, and review the absolute Docker CLI executable, local `unix:///…` socket URI, hexadecimal container ID (12–64 characters), container user/UID:GID, absolute Linux workspace root, Cargo and rust-analyzer executable paths. Check the container-specific trust acknowledgement and choose **Start container workspace**. This is separate from the existing Dev Containers lifecycle CLI panel. Opening a local project or either panel launches no Docker process. No inspect/list, image pull, container creation/start, lifecycle hook, automatic attachment or installation occurs in this workspace mode.

The container must already run and contain Bash, env, find, Python 3, setsid, timeout, Cargo, rustc/rustdoc beside Cargo, and rust-analyzer. A failed preflight reports an error instead of downloading tools. Only local Unix sockets are supported in this implementation; TCP/SSH Docker contexts and Windows named pipes are unavailable. All Docker command arguments are separate values: `docker --host SOCKET exec -i --workdir ROOT --user USER ID PROGRAM ARGS…`. Host Docker configuration variables (`DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_TLS`, `DOCKER_TLS_VERIFY`, `DOCKER_CERT_PATH`, `DOCKER_API_VERSION`, `DOCKER_CONFIG`) are removed for all launches, including the file bridge, Cargo and rust-analyzer. No PTY, `--privileged`, host shell or PowerShell is used. The Linux-side shell scripts are internal bounded scripts with validated/quoted paths; editor contents pass through JSON stdin rather than shell interpolation. The explicitly selected Docker CLI and daemon must be trusted: Docker socket access may grant host-level capabilities.

The existing remote editor supplies Rust syntax, definition, plain completion edits, hover, versioned diagnostics, Cargo check/build/test, diagnostic navigation, cancellation and reviewed writes. Its buffers belong to the frozen transport settings, independently of local documents. Linux file URIs are resolved only beneath the chosen container root, never forwarded to the local editor as an alias. Windows paths and paths outside that root are rejected. Changing daemon/container/root/tool settings revokes trust; a session with unsaved buffers refuses switching to a different identity. Disconnect retains edits. Ordinary build/run configurations and the local debugger do not move into the container.

Files use the existing bounded Linux JSON bridge: regular UTF-8 sources up to 512 KiB, editable writes up to 64 KiB, explicit preview and confirmation, content recheck before replacement, BOM/CRLF preserved. Symlinks/special files and path traversal are rejected. Writes are not an atomic compare-and-swap against concurrent container writers. Cargo refuses unsaved remote buffers. Language-server and Cargo jobs retain the existing bounded output, deadlines, Linux process-group isolation and stdin EOF watchdogs. Killing a Docker exec client alone does **not** establish that the process inside a real container stopped; the watchdog is required, and actual Docker-disconnect semantics remain unverified here.

## Evidence and remaining validation

Y-09 remains **partial**. This host cannot run Docker containers due to its AppArmor/runtime restrictions. Tests use an executable Linux Docker-argv shim that validates the exact selected socket/container/user/root and then execs real Linux tools. This proves the CLI argument contract and native IDE pipeline, not Docker daemon/runtime behavior, mount/user isolation, container restart behavior or actual daemon-side cancellation.

The native fixture uses a real Rust Cargo workspace and rust-analyzer: no process before trust, Start, definition/completion, edited source preview/confirm, successful Cargo tests, a real type error and diagnostic navigation, local namespace separation, dirty-buffer preservation and refused container-ID changes. A subprocess fixture inherits deliberately poisoned Docker variables and verifies their absence in actual bridge, Cargo and RA launches without changing global test-process environment. Backend tests verify strict endpoint/argument forms, stale-file refusal and prompt cancellation of a real sleeping Rust build script. A separate test closes stdin without killing the CLI shim and proves that the Linux EOF watchdog stops the real Rust build process; propagation of that EOF through an actual Docker daemon still requires runtime validation. Existing SSH and WSL transport tests remain applicable regression checks. A real already-running Docker container must exercise this same flow plus EOF/disconnect cancellation before Y-09 can be marked ready. Dev Containers Up/Exec lifecycle validation remains pending separately.

References: [Docker exec command and options](https://docs.docker.com/reference/cli/docker/container/exec/) and [Docker daemon socket access](https://docs.docker.com/engine/security/protect-access/). No Docker executable, image or container asset is distributed.
