# Change Rust function signature

Put the caret on an ordinary free function, then use **Code → Change Rust Function Signature** or Find Action. The project must already be trusted and rust-analyzer must be available. The native window can reorder, rename, remove or add parameters, change their types and change the return type. A new parameter requires a literal argument for existing calls. Review the proposed edits, then explicitly apply them. Applying changes edits buffers, including opening closed callers from the checked snapshot; it does not save files or run Cargo. The window offers a guarded undo for the entire operation.

This is a conservative workspace refactoring, not an API compatibility checker. External callers are not updated. Type changes may need further body changes before the program compiles. Methods, trait declarations, foreign functions, attributed functions, generated or unknown macro contexts, complex parameter patterns and function-value uses are refused. Unknown references stop the operation instead of silently producing a partial rewrite. Macro argument calls are supported only inside explicitly recognized standard expression macros whose definitions rust-analyzer resolves to the standard library.

References use rust-analyzer definition identity, not textual substitution. Because references through `use ... as ...` can be omitted from a reference response, a bounded source scan also checks candidate names and import aliases against definition identity. Parameter renames use semantic rename edits, preserving struct field shorthand meaning. Parameter removal checks semantic references and independently resolves matching body names, allowing unrelated shadowing. Reordering or removing an argument that may have effects is refused; literals and simple identifiers passed to existing primitive scalar parameters are supported. Renaming or adding/removing a binding in a body containing macros is refused.

Snapshot collection, parsing, semantic requests, disk checks and preview generation run on cancellable workers. Loading and applying verify all scanned Rust sources and Cargo/toolchain configuration files, including previously absent configuration paths. Project trust, analysis connection, member configuration, document versions, disk epochs and form values must still match. A source change, new source file, analysis restart or closed-file modification invalidates the proposal. Apply rechecks disk content on a worker before editing the checked buffers. Edits, cancellation and closing the window during verification prevent applying its result. Undo refuses the whole operation if any affected buffer has changed.

Files are regular UTF-8 text, bounded to 2 MiB each, 16 MiB of Rust source and 256 Rust files. The scan excludes symlinks, build output, VCS directories and unrelated nested Cargo projects. Configuration snapshots have a separate 16 MiB budget. At most 64 members/open Rust buffers, 32 parameters and 4096 references/edits are accepted. Workers have a 45-second deadline and bounded source traversal. Reads check cancellation between chunks; Unix opens use nonblocking/no-follow flags and verify descriptor metadata. BOM and CRLF are retained in the document's save policy.

Validation uses real Cargo workspaces and rust-analyzer: alias calls inside `assert_eq!`, semantic shorthand renaming, unused parameter removal despite shadowing, addition and reorder produce two-file proposals whose Rust output compiles and runs. Native UI tests exercise preview, checked apply, unsaved buffers and undo. Negative fixtures reject alias function values, used parameter removal, effectful argument reordering and externally changed closed callers. Pure AST tests cover comments, mutable parameters, macro arguments and invalid/injected input.

The implementation uses CrabCraft's existing tree-sitter Rust syntax and rust-analyzer LSP integration. Protocol references: [LSP references](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_references), [definition](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_definition) and [rename](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_rename). No new distributed assets or runtime dependencies.
