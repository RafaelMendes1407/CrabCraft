# Project tree reads

The native Project panel reads directories and static `.csproj` text in a shared two-worker pool. Drawing, expanding a row and showing a context menu use memory only. A cache miss queues work and returns immediately; loading and read errors are visible. Cancel stops pending reads cooperatively. Refresh clears caches/errors and retries. A workspace path change cancels pending work and clears its caches; reply IDs reject late results after invalidation, refresh or workspace switches.

Directory reads inspect at most 20,000 entries and retain at most 5,000 visible entries / 8 MiB of names and paths. The combined cache holds at most 256 directory/project keys, 50,000 directory entries and 64 MiB of estimated payload. Error storage is capped at 256 keys. At most 64 reads may be pending; a full queue produces a visible error with an explicit Refresh retry. The UI accepts at most two worker replies per frame and constructs at most 20,000 rows / 64 nesting levels. Reaching a cache/input limit refuses the result; it does not present a truncated directory as complete.

Project XML reads accept regular UTF-8 files up to 2 MiB; on Unix the open refuses symlinks and does not block on a FIFO without a writer. Cancellation and file length/mtime are checked while reading. Parsing is static and does not invoke MSBuild, Cargo, build scripts, proc macros or any project command. Framework/package/reference counts and string lengths are bounded. The context menu detects Cargo/.NET roots from cached listings instead of probing the filesystem while drawing.

Cancellation cannot interrupt a filesystem syscall already waiting in the kernel. Such a call occupies one of the two workers, never the UI thread; it cannot create unbounded threads or a new read queue. Estimates bound retained payload, not allocator overhead. The panel does not watch or automatically refresh every directory; explicit Refresh remains available after queue/limit/cancellation errors.

Evidence: seven Explorer tests include a native egui tree in a real Cargo project (load/Refresh), cancellation and stale reply rejection, workspace switches, a directory over 5,000 files with recovery, FIFO rejection, static project XML and existing icon/exclusion behavior. A `build.rs` marker remains absent throughout. Four accessibility tests continue to pass with asynchronous loading, including real parent hierarchy, virtualization and keyboard selection. These are tree-read proofs, not claims about every filesystem operation elsewhere in the application.

Final private Linux/X11 Orca verification after this migration: five editor snapshots, four reader utterances, source character geometry and actual nested Explorer parents verified, with no project code executed. The session script is scripts/accessibility/orca_session.py; it observes AT-SPI and does not inject input into the real window. This does not verify other desktop/readers or physical audio output.
