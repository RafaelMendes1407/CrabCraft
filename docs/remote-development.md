# Remote Rust workspace

Use **Code → Remote Rust workspace…** or Find Action to open the native remote workspace mode. It is independent of the local workspace: server paths and language-server documents remain in a remote namespace, and remote files never enter the local document list, save queue, session or file watcher. Opening the window, opening a local project or entering configuration runs no SSH command.

Supply a Linux SSH host, port, user, private key, independently verified `known_hosts` file, absolute remote workspace root, and absolute remote Cargo and rust-analyzer executable paths. Check the explicit host/workspace trust box, then choose **Start remote workspace**. Start invokes remote tools: Cargo metadata, build scripts and procedural macros may run during rust-analyzer indexing. Changing the configuration revokes the trust selection before a connection can start. Trust and credentials are memory-only. Nothing installs a remote tool or service.

The host needs OpenSSH/SFTP, Bash, `find`, `setsid`, GNU `timeout`, `mktemp`, `mkfifo`, Cargo/rustc and rust-analyzer. The Cargo executable directory is prepended to `/usr/bin:/bin` for the remote process; no local project environment, SSH agent, proxy, forwarding or user SSH configuration is inherited. The existing key-only OpenSSH transport uses strict host-key verification, batch mode and private temporary credential snapshots. Password prompts and host-key acceptance prompts are unsupported.

After Start, select a source from the bounded remote source list or enter a relative path under the remote root. The native Rust editor provides local editing/undo and background syntax parsing. Definition navigation opens another remote buffer; hover shows plain documentation, and completion applies a checked plain LSP text edit only when the originating document version still matches. Snippets, additional import edits, cross-root navigation and other remote refactorings are visibly unsupported. URI decoding never canonicalizes or reads local desktop files, including Windows drive paths. Navigation distinguishes LSP UTF-16 positions from Rust compiler character columns and handles a closed target's UTF-8 BOM.

**Preview remote upload** checks the remote baseline on a worker and shows before/after content. **Confirm remote overwrite** checks it again before SFTP uploads and renames a temporary file. Editing the buffer invalidates its pending preview. An edit made during upload is retained as dirty after the uploaded baseline is recorded. SFTP provides no atomic content compare-and-swap: concurrent writers can race the final check, and cancellation may leave an already committed upload or temporary file. This is not a remote file lock. BOM and line-ending policy are retained. Reload is explicit, cancellable, version-guarded and asks before discarding dirty text.

Remote Cargo **check**, **build** and **test** are explicit actions. They refuse dirty remote buffers; upload or undo changes first. Cargo receives structured JSON output; its diagnostics link back to remote source buffers. Output is bounded and virtualized. Editing a buffer invalidates pending semantic results and Cargo diagnostics. rust-analyzer's automatic Cargo check/check-on-save is disabled; its native diagnostics still decorate matching synchronized document versions. Start can still run metadata/build-script/proc-macro analysis as disclosed by its trust prompt.

Cancel stops the current transfer/Cargo job or semantic request. Disconnect closes the remote analyzer and cancels jobs while keeping buffers in memory, read-only. Reconnecting to the same settings resends those buffers without discarding dirty edits; their saved remote baseline is checked again before any upload. Switching settings refuses to discard dirty buffers. Closing dirty buffers requires explicit confirmation. A local workspace close or CLI/IPC switch disconnects remote analysis but preserves remote buffer identities, baselines and unsaved edits; it never discards them or queues them for local saving. While this modal mode is open, global Save/Build/Test and analysis commands route to remote controls; unsupported IDE commands do not operate on the hidden local workspace. Local Save cannot accidentally save a remote path.

Remote Cargo runs in an isolated process group with an SSH-stdin EOF watchdog, exit/HUP cleanup and a 120-second host timeout. Remote rust-analyzer uses a separate group and FIFO input watchdog; closing SSH input kills its group and cleans up the private FIFO directory. These mechanisms complement local process-tree cancellation; they do not claim to control deliberately detached project daemons. Credentials and temporary client files are held only for each operation/session. The shared LSP transport bounds stderr to 8 KiB per line, 2 MiB/8192 lines per session and reports a typed transport error before terminating an overproducing peer.

Limits: 512 listed files, 16 open remote buffers, 512 KiB per downloaded source (above 64 KiB is read-only), 64 KiB per editable/uploaded source, 2 MiB process output, 128 KiB per process line, 4096 displayed output lines and 1000 Cargo diagnostics. SSH transfer/start discovery has a 15-second deadline; the analyzer handshake has 45 seconds, semantic requests 20 seconds and Cargo 125 seconds including transport shutdown. No background polling downloads remote file contents. The file list is a startup snapshot, not a live remote Explorer. Creating/deleting files, project-wide remote refactoring, remote debugging/session persistence and terminal run configurations are outside this mode; separate Remote Files and remote debugging workflows remain available.

Validation uses a real key-only OpenSSH connection on loopback, not a mocked SSH executable: remote rust-analyzer definition lookup; actual Cargo check/build/test; structured compiler diagnostics; reviewed SFTP editing; host-key rejection before project code; and remote build-script cancellation. Native UI coverage exercises explicit trust, separate remote tabs, semantic completion, preview/confirm upload and process output. Additional pure tests cover path confinement and Unicode/URI positions. The fixture runs on the same machine/UID over an actual SSH session; it does not demonstrate a physically separate machine or WAN behavior.

Public references: [OpenSSH client configuration](https://man.openbsd.org/ssh_config), [rust-analyzer configuration](https://rust-analyzer.github.io/book/configuration.html), [LSP document synchronization](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_synchronization). No new assets, packaged servers or runtime libraries are distributed.
